# MoodLite 完全离线轻量版设计规范

**状态：** 方案 A 已获批准，等待书面规范复核  
**日期：** 2026-09-10  
**基线：** `main` 分支 `ed5792e`

## 1. 目标

将 MoodLite 收敛为一款完全离线、无需登录的轻量情绪日记。用户从首次启动到日常记录、查看历史、编辑删除、查看月度统计、设置本地提醒和使用桌面卡片，全程不需要账号或网络连接，情绪数据仅保存在设备本地。

## 2. 成功定义

完成后的应用必须同时满足以下条件：

1. 启动流程中不存在登录、注册、会员、额度或账号状态。
2. 运行时代码不创建网络请求，不包含 AI 服务地址、API Key 或远程内容依赖。
3. 应用不声明 `ohos.permission.INTERNET` 和未使用的媒体读取权限。
4. 应用内不打开网页；“反馈”入口删除，“数据与隐私”和“关于”均为本地页面。
5. 飞行模式下可以完成首次启动、创建记录、查看、编辑、删除、统计、主题切换、本地提醒和 2×2 桌面卡片的核心流程。
6. 编辑记录不得改变原始创建时间或日期；保存和删除失败时不得伪装成功。
7. 月度统计仅使用当前月份数据，记录天数按不重复日期计算。
8. 桌面卡片进入应用时，必须先完成本地数据初始化，且外部参数不能导航到任意页面。
9. 仓库提供可重复执行的离线约束检查和核心逻辑测试。

## 3. 产品范围

### 3.1 首发保留

- 首次启动欢迎页。
- 五档情绪评分（-2 到 2）。
- 文字和预设/自定义标签记录。
- 今日概览及本地固定关怀文案。
- 时间线、详情、编辑和删除。
- 月度热力图、情绪占比、记录天数和月内标签分布。
- 深色模式及现有主题选择。
- 系统本地定时提醒。
- 保存时的本地触觉反馈。
- 2×2 桌面情绪卡片。

### 3.2 删除或延期

- Dify、DeepSeek 及所有 AI 分析、AI 建议、AI 对话。
- 登录、注册、会员、订阅、配额及多用户本地账户。
- 外部反馈表单和外部“关于”页面。
- 图片选择、图片读取和位置记录功能。
- 成就模型、成就判定、成就弹窗及成就素材。
- 2×4 桌面卡片和无界面入口的快捷记录处理器。
- 云备份、导出和云同步。

已有 `MoodRecord` JSON 中的 `images` 和 `location` 字段作为旧数据兼容字段处理：首发版不展示、不写入新内容、不申请相关权限；读取旧数据时允许字段存在，避免破坏已有记录。

## 4. 总体架构

应用继续使用 HarmonyOS Stage 模型、ArkTS、ArkUI 和 Preferences。无需引入后端、数据库服务、网络库或第三方 SDK。

```text
EntryAbility
    ↓ 始终加载 Index
Index
    ↓ 初始化 DataManager
Welcome（首次启动）或 MainPage（普通启动/卡片入口）
    ├── HomeTab：今日概览、本地固定文案
    ├── TimelineTab / EntryDetail / AddEntry：本地记录闭环
    ├── StatsContent：纯本地聚合
    └── Profile：提醒、主题、本地隐私与关于页面

Preferences ← DataManager → 2×2 EntryFormAbility
```

所有业务数据流都以 `DataManager` 的本地缓存和 Preferences 为单一事实来源。UI 不直接访问远程服务，也不维护第二套账户态或 AI 状态。

## 5. 启动与导航

### 5.1 普通启动

`EntryAbility` 始终加载 `pages/Index`。`Index` 初始化 `DataManager` 后，根据 `first_launch` 进入 `Welcome` 或 `MainPage`。不存在认证初始化和登录分支。

### 5.2 桌面卡片启动

卡片传入的导航意图只允许以下目标：

- `pages/MainPage`
- `pages/AddEntry`

`EntryAbility` 不再直接加载目标页面，而是先将经过白名单校验的目标和 Tab 参数写入临时 `AppStorage`，然后加载 `Index`。`Index` 等待 `DataManager` 初始化完成后再消费目标并导航，解决冷启动时主页面读取空缓存的问题。

应用已经在前台时，`onNewWant` 同样校验白名单；非法目标被忽略并记录错误日志。

## 6. 离线化设计

### 6.1 删除联网实现

- 删除 `entry/src/main/ets/common/utils/AiAgentClient.ets`。
- 删除 `AddEntry` 中 `analyzeMood` 调用和 `activeIntent` 写入。
- 删除 `HomeTab` 中 AI 类型、状态、解析、动画和 AI 建议卡片。
- 删除 `entry/build-profile.json5` 中 `DIFY_API_KEY` 与 `DIFY_BASE_URL`。
- 删除模块清单中的 `ohos.permission.INTERNET`。
- 删除模块清单中的 `ohos.permission.READ_IMAGEVIDEO`。

`ohos.permission.PUBLISH_AGENT_REMINDER` 用于本地系统提醒，`ohos.permission.VIBRATE` 用于本地触觉反馈，继续保留。

### 6.2 本地信息页面

设置页移除“给我们反馈”，新增“数据与隐私”，并保留“关于 MoodLite”。两者均导航至本地 ArkUI 页面：

- `DataPrivacyPage`：说明记录、标签、主题和提醒配置仅存于本机；应用不创建账号、不上传情绪内容、不调用第三方 AI；卸载或清空数据后的恢复限制也要写清楚。
- `AboutPage`：展示应用名称、版本、产品定位和“完全离线”说明，不包含网址或远程图片。

页面加入 `main_pages.json`，不使用 `Want` 打开浏览器。

### 6.3 离线约束检查

仓库新增一个 Node.js 静态检查脚本，仅扫描运行时源码与清单，若发现以下内容则返回非零状态：

- `@ohos.net` 或 `@kit.NetworkKit` 等网络 API 导入。
- `http://`、`https://` 运行时地址。
- `DIFY`、`DEEPSEEK`、`API_KEY` 等远程服务配置。
- `ohos.permission.INTERNET`。
- `AuthManager`、`LoginPage`、`memberType`、`AIAgentChatPage` 等账户或 AI 残留。

依赖锁文件中的包下载地址属于构建期元数据，不纳入运行时检查。

## 7. 轻量化设计

### 7.1 移除成就系统

- 删除 `Achievement` 模型、`AchievementChecker`、`AchievementDialog` 和成就图片。
- `HomeTab` 只负责今日情绪概览、空状态和记录入口。
- `DataManager` 不再读写成就、待展示队列或触发成就通知。
- 已有 Preferences 中的成就键可以保留为无害旧数据；新版不再读取或更新它们。

### 7.2 仅保留 2×2 卡片

- `form_config.json` 仅注册 `MoodWidgetCard`。
- 删除 `widget1` 目录、2×4 卡片文案和专用素材。
- 删除当前没有卡片界面触发的 `quick_log` 消息处理器及独立写入入口，避免形成第二套记录写入路径。
- 2×2 卡片只展示本地今日概览并打开应用，不在后台创建记录。

### 7.3 清理未启用功能

删除未注册的备份能力、备份配置和导出/云下载图标。首发版不承诺恢复、跨设备同步或导出能力，隐私页面明确提醒用户数据仅在本机。

## 8. 记录数据与正确性

### 8.1 编辑语义

编辑操作更新 `score`、`text` 和 `tags`，但保留原记录的：

- `id`
- `timestamp`
- `dateStr`
- 兼容字段 `images`
- 兼容字段 `location`

`EditBridge` 传递完整记录副本，`AddEntry` 保存时以原记录为基础创建更新后的不可变对象。不得使用 `Date.now()` 覆盖旧记录日期。

### 8.2 本地数据兼容

`DataManager` 初始化时对 Preferences 中的记录进行校验和规范化：

- 无法解析的整体 JSON 不导致永久白屏；应用回退为空列表并记录错误。
- 缺少 `tags`、`images` 或 `location` 的旧记录补默认值。
- 分数限制为 -2 到 2 的整数；无有效 ID、时间戳或日期的条目被跳过。
- 记录按 `timestamp` 倒序排列，保证首页和时间线默认展示最新内容。

写入继续串行化，只有 Preferences `flush()` 成功后才更新内存缓存和桌面卡片。

### 8.3 删除反馈

详情页删除记录后检查返回值：成功才返回时间线；失败则留在当前页并显示“删除失败，请重试”。按钮在操作期间防重复点击。

## 9. 统计口径

- 统计缓存不再使用“记录数量 + 第一条 ID”作为变更标识。记录数组发生变化时直接重建月份索引；首发数据量下优先保证正确性。
- 标签分布只传入当前年月的 `monthRecords`。
- 月度“记录天数”按不重复 `dateStr` 计算，同一天多条记录只计一天。
- 2×2 卡片中的记录天数使用相同的去重口径。
- 热力图、正向/平静/低落占比仍按当月记录条数聚合。

## 10. 提醒状态

打开提醒开关时，界面先显示时间选择器，不提前把状态写成开启：

1. 用户确认时间。
2. 系统提醒发布成功。
3. 才保存提醒 ID、时间并将开关设为开启。

用户取消时间选择时，开关保持关闭。关闭已有提醒时，只有系统取消成功后才清除提醒 ID 和开关；失败则维持原状态并提示用户重试。`ReminderManager` 的启用与取消均返回可判断的结果。

## 11. 错误处理

- 本地数据初始化失败：`Index` 显示可重试的本地错误态，不绕过初始化直接进入主页面。
- 保存失败：停留在编辑页，保留用户输入，允许重试。
- 删除失败：停留在详情页，记录仍可见。
- 提醒发布或取消失败：状态与系统实际结果保持一致，并显示短提示。
- 非法桌面卡片路由：忽略目标并进入安全默认页面。
- 离线运行：不存在需要显示“网络异常”的业务分支。

## 12. 测试策略

### 12.1 静态离线测试

先写一个会在当前代码上失败的离线约束测试，证明它能检测 Dify 配置、网络 API、外部 URL 和 `INTERNET` 权限。完成删除后，该测试必须通过。

### 12.2 ArkTS 单元测试

用真实纯函数覆盖：

- 编辑记录保留创建日期和兼容字段。
- 旧数据规范化、非法记录过滤和倒序排列。
- 当月标签分布不混入其他月份。
- 同日多条记录只计一个记录日。
- 卡片记录天数与统计页口径一致。
- 合法/非法桌面卡片目标白名单。

测试必须先在现有行为上以预期原因失败，再写最小实现使其通过。

### 12.3 构建与人工验收

- 运行全部静态检查和 ArkTS 测试。
- 使用项目声明的 HarmonyOS API 21 工具链完成 Debug 与 Release 构建；不得仅为适配本机 API 26 环境而擅自提高最低版本。
- 在真机飞行模式下验证首次启动和完整记录闭环。
- 重启应用后检查数据、主题和提醒配置仍然存在。
- 添加 2×2 卡片，冷启动应用并验证卡片更新。
- 检查安装包权限清单仅包含实际使用的本地能力。

## 13. GitHub 与飞书同步规则

开发过程中的联网同步属于项目协作行为，不是应用运行时能力，因此不影响“完全离线”的产品定义。每个可以独立验证的实施批次都遵循以下顺序：

1. 测试先失败，再完成最小实现并使本批次相关测试及回归测试通过。
2. 只暂存本批次文件，不包含用户已有的未跟踪文件或无关修改。
3. 创建包含单一主题的 Git 提交，并推送到 GitHub 的 `origin/main`。
4. 更新现有 MoodLite 飞书项目文档，记录本批次目标、实际修改、Git 提交哈希、验证结果和剩余工作。
5. 重新读取飞书文档对应章节，确认远端内容已经写入。

GitHub 推送或飞书更新失败时，不得声称该批次已同步；保留本地成果并继续重试，确实需要用户授权或外部状态变化时明确报告阻塞。飞书文档不得记录 API Key、签名密码、访问令牌或用户情绪数据。

## 14. 实施顺序

1. 建立离线约束测试，并删除 AI、网络配置、外链和无用权限。
2. 移除成就、2×4 卡片、快捷记录和未启用备份代码。
3. 修复编辑语义、本地数据规范化和删除反馈。
4. 修复统计口径。
5. 修复提醒状态和桌面卡片冷启动导航。
6. 添加本地隐私/关于页面，更新应用与卡片文案。
7. 运行静态检查、单元测试、构建和飞行模式验收。
8. 每个完成的批次均按第 13 节同步 GitHub 与飞书文档。

## 15. 非目标

本轮不实现以下内容：

- 任何形式的 AI 或规则式“伪 AI”对话。
- 登录、会员和付费。
- 云同步、云备份、导出或跨设备迁移。
- 图片、位置、音频或视频日记。
- 社交、分享或在线反馈。
- 新的图表类型、复杂连续打卡或游戏化系统。

这些能力未来如需加入，必须作为独立版本重新评估隐私、权限、数据迁移和网络架构，不能在本首发版中以隐藏代码或功能开关保留。
